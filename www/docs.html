Documentation

FakaApache is a small educational C++17 HTTP server for static files and optional HTTP reverse-proxy forwarding.

Run the server

Run it from the project root so the default configuration can find the www directory:

fakaapache.exe --config siteconfig.fakaapache

The default site listens on 127.0.0.1:8080.

Build on Windows

MSVC and CMake are the recommended Windows toolchain. On the first configure, CMake automatically downloads a pinned vcpkg checkout and installs OpenSSL:

cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release

The executable is created at build/Release/fakaapache.exe. CMake requires OpenSSL development libraries for TLS support.

Configuration

Configuration uses INI-style sections. Global settings belong in [server]; virtual-host settings use sections such as [vhost example.com].

[server]
port = 8080
root_directory = www
SettingDefaultPurpose
bind_address127.0.0.1IPv4 address on which the server listens.
port8080Listening port, from 1 through 65535.
root_directorywwwDirectory containing static files.
index_fileindex.htmlDefault file for requests ending in /.
server_namelocalhostLabel shown in startup logs.
tls_certificateunsetPEM certificate path; enables TLS with tls_private_key.
tls_private_keyunsetMatching PEM private-key path.
rate_limit_requests_per_minute120Token-bucket refill rate per client IP.
rate_limit_burst20Maximum immediate requests per client IP.
auth_usernameunsetOptional Basic Authentication username.
auth_passwordunsetMatching plaintext password; protect the configuration file.

HTTP forwarding

Set both values to forward GET requests to another HTTP application:

forward_address = 127.0.0.1
forward_port = 3000

FakaApache opens one upstream connection per request and returns 502 Bad Gateway if the upstream cannot be reached. GET and POST are supported; POST bodies require Content-Length and are limited to 10 MiB. Forwarding is intended for local or trusted services.

Keep-alive and ranges

Static HTTP/1.1 clients may reuse a connection for up to 100 requests. Static GET and HEAD requests support one byte range, for example Range: bytes=0-1023. Multiple ranges are not supported. Forwarded connections are closed after each request.

TLS and rate limiting

Set both PEM paths to enable TLS:

tls_certificate = certs/server.crt
tls_private_key = certs/server.key
rate_limit_requests_per_minute = 120
rate_limit_burst = 20

Rate limiting is applied per client IP using a token bucket. TLS is disabled when either path is unset.

Authentication and compression

auth_username = admin
auth_password = change-me

Set both credentials to enable HTTP Basic Authentication for all routes. Use TLS with authentication because the configured password is plaintext and Basic credentials are transport-encoded, not encrypted. Static responses are gzip-compressed when the client advertises Accept-Encoding: gzip.

Tested features

The Windows integration tests exercise the server with real HTTP requests. The Command Prompt suite can be run without PowerShell:

tests\integration_test.cmd http://127.0.0.1:8080
  • GET and HEAD responses, including keep-alive headers.
  • Single-byte ranges, unsatisfiable ranges, and Content-Range.
  • Gzip negotiation, including gzip;q=0.
  • Missing files, malformed URLs, and directory-traversal rejection.
  • Unsupported methods, static POST rejection, and Allow headers.
  • Basic Authentication when FAKAAPACHE_AUTH_USER and FAKAAPACHE_AUTH_PASSWORD are set; the PowerShell suite also tests rate limiting.
  • TLS and proxy forwarding require dedicated configurations and are not enabled by the default smoke test.

Operational boundaries

  • Static paths are canonicalized and prevented from escaping the document root.

MinGW-w64: compatibility support is scheduled for removal. Use MSVC and CMake for new Windows builds.
